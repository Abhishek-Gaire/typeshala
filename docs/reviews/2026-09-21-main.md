## Major

### 🟠 Three shipped sentence lessons are still impossible to complete (`?` untypeable), `src/data/lessons/ne-traditional.json:126`

**Problem**: `nt-sentences-a/b/c` (orders 17-19, lines 126/134/142) contain ASCII `?`. `PREETI_MAP` maps `?` -> `रु` (`src/domain/preeti.ts:167`) and no sequence produces `?` (verified: `sequenceForPreeti("?") === ""` and `advancePreeti("", "?")` commits `रु`). On the `?` unit the lit key commits `रु`, the session counts a miss and holds the cursor, so `done` can never become true. The updated allowlist at `tests/data/lessons/ne-traditional.test.ts:31` skips exactly this unit, so the suite cannot catch it.
**Why it matters**: The spec's Consequences promise "Every shipped prompt becomes typeable, so the course keeps its core promise" and "The course no longer ships a lesson nobody can finish" (`docs/specs/0018-preeti-map-correction-lesson-coverage/index.md:56`, `0018-lesson-coverage.md:84`). Both are false as shipped. The same completability argument that removed `nt-punctuation` (`rationale.md:7`) applies to these three lessons. Parent criterion S1 deliberately keeps an ASCII punctuation exception, so the spec contradicts itself rather than the author ignoring it.
**Suggested fix**: Decide the exception now. Either give `?` a real home (the chart/reference maps `<` -> `?`, and `-`/`_` -> `(`/`)`, which would also restore punctuation typing), or drop/replace `?` in the three sentence prompts. If it is deliberately deferred, correct the spec's Consequences, add a Follow-up item, and make the test comment name the exception explicitly so it is not mistaken for coverage.

## Minor

### 🟡 Session test claims the flush path but exercises the auto-settle path, `tests/features/typing/useTraditionalSession.test.tsx:178`

**Problem**: The test named "commits the aa mark from f on prompt end through the flush path" types `s`,`f` against prompt `का`. In `useTraditionalSession.typeChar`, a key with no commits that exactly settles to the expected unit is committed immediately by the auto-settle branch (`src/features/typing/useTraditionalSession.ts:186-195`), so buffer `f` never survives to the prompt-end flush (`:225-235`) or the space flush (`:141-145`). The test would still pass if both flush paths were deleted, and child spec AC-4 ("stays pending and commits ... through the existing flush path", `0018-map-correction.md:12`) is not demonstrated at session level. The spec's stated tradeoff ("`f` now buffers one press ... slightly later than today", `index.md:61`) also does not match session behavior when `ा` is expected.
**Why it matters**: The riskiest part of this change is the new pending semantics of `f`; the session-level test names a mechanism it does not exercise, so a regression in the flush path would go unnoticed and the spec's behavioral claim is inaccurate.
**Suggested fix**: Either add a session case that actually leaves `f` pending into the flush path (if one is reachable) or rename the test and restate AC-4 to the real behavior: `f` settles immediately when `ा` is the expected unit and buffers only while composing `ो`/`ौ` or after a wrong prefix.
